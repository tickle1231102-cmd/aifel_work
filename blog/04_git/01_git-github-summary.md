Git과 GitHub의 핵심 개념을 정리했습니다.

## 1. Git 정리

**Git 핵심 기능**: 버전 관리 도구
프로젝트 흐름의 구조적 변화 기록 및 복구 등 관리

### 주요 개념

- **blob** — 파일 내용
- **tree** — 디렉터리 구조
- **commit**
  - 특정 트리, 부모 커밋, 작성자, 메시지
  - 특정 시점의 변경 기록
- **브랜치**
  - "여기서부터 다른 가능성을 실험해보겠다."
  - 메인에 영향 주지 않고 다양한 기능 추가 및 시도, 수정 가능 (안전한 실험 가지)
  - 특정 커밋에서 독립적으로 작업을 이어갈 수 있는 작업 흐름
- **merge** — 가지 합치기

## 2. GitHub 정리

Git 저장소 온라인 보관 및 협업 서비스

### 원격 저장소

- **repository**: 저장소
- `git push`: 내 로컬 저장소 → 원격 저장소
- `git pull`: 원격 저장소 → 내 로컬 저장소
- **깃허브에 올린다** = 내 Git 저장소 변경 이력을 GitHub 원격 저장소와 동기화한다

### 협업 기능

- **Issue** — 할 일, 버그, 제안 등을 기록하는 게시글
- **Pull Request(PR)** — 내가 만든 변경사항을 원래 프로젝트에 합쳐달라고 제안하는 요청
- **Code Review** — 변경된 코드를 다른 사람이 읽고 의견을 남기는 과정
- **Actions** — 테스트, 빌드, 배포 같은 작업을 자동으로 실행하는 GitHub의 자동화 기능

### `git diff`

이전 상태와 현재 상태의 차이를 보여주는 기능입니다. 작업 전 상태를 커밋해두었다면,
AI가 원하지 않는 방향으로 코드를 바꿨을 때 이전 커밋으로 돌아갈 수도 있습니다.

## AI 시대에 Git이 중요한 이유

커밋 메시지는 단순한 로그가 아니라, **판단의 단위**입니다.

> "버그 수정"보다 "로그인 실패 시 토큰 갱신 루프를 막기 위해 만료 조건 추가"가 훨씬 낫습니다.

나중에 AI에게 다시 질문할 때도 이런 기록은 강력한 맥락이 됩니다.
