Todo App · DB Schema

SQLite로 만드는 Todo 앱 DB 구조

할 일 CRUD에 마감일과 태그(카테고리)를 얹은 3개 테이블 설계. 파일 하나(todo.db)로 끝나는 로컬 무료 DB라 별도 서버 없이 껐다 켜도 데이터가 남습니다.

1. ERD — 테이블 관계

todos와 tags는 서로 여러 개씩 물릴 수 있는 관계라, 직접 연결하지 않고 연결 테이블 todo_tags를 하나 둡니다 (다대다 N:M).

2. 테이블 상세

각 열의 타입과 제약 조건. SQLite는 타입에 관대해서(동적 타이핑) INTEGER/TEXT 정도로 충분합니다.

3. 커스텀 기능 → 스키마 대응

마감일 표시todos.due_date 한 열로 처리. 인덱스 idx_todos_due_date를 걸어두면 정렬·필터가 빨라집니다.
카테고리(태그)tags + todo_tags 두 테이블로 다대다 지원. 태그를 나중에 추가/삭제해도 todos 구조는 그대로예요.
오늘 할 일만 보기새 열 없이 WHERE due_date = date('now') 조건 쿼리로 해결.
검색WHERE title LIKE '%키워드%'로 시작하고, 데이터가 많아지면 SQLite FTS5 가상 테이블로 업그레이드하면 됩니다.

4. 생성 SQL

그대로 실행하면 위 구조가 만들어집니다.

-- 할 일 본체
CREATE TABLE todos (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,
  memo        TEXT,
  is_done     INTEGER NOT NULL DEFAULT 0,
  due_date    TEXT,                          -- 'YYYY-MM-DD', 없으면 NULL
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 태그(카테고리)
CREATE TABLE tags (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  name   TEXT NOT NULL UNIQUE,
  color  TEXT
);

-- todos ↔ tags 다대다 연결
CREATE TABLE todo_tags (
  todo_id  INTEGER NOT NULL REFERENCES todos(id) ON DELETE CASCADE,
  tag_id   INTEGER NOT NULL REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (todo_id, tag_id)
);

-- 자주 걸리는 조회 조건에 인덱스
CREATE INDEX idx_todos_due_date  ON todos(due_date);
CREATE INDEX idx_todos_is_done   ON todos(is_done);
CREATE INDEX idx_todo_tags_tag   ON todo_tags(tag_id);
